# MSC4563: `direct_message` push rule type

Matrix clients and servers use push rules to decide which notifications get sent
to the user, but current default push-rule behavior does not work well in
conjunction with bridges, nor is it as flexible to the end-user, which might
want "Direct Message Groups" to still give (push) notifications.

## Proposal

The `direct_message` push rule is directly related to the `m.direct` account data. It
is defined like below, replacing the default `.m.rule.encrypted_room_one_to_one`
and `.m.rule.room_one_to_one` rules.

```json
{
    "rule_id": ".m.rule.encrypted_direct", // or .m.rule.direct
    "default": true,
    "enabled": true,
    "conditions": [
        {
            "kind": "direct_message"
        },
        {
            "kind": "event_match",
            "key": "type",
            "pattern": "m.room.message"
        }
    ],
    "actions": [
        "notify",
        {
            "set_tweak": "sound",
            "value": "default"
        }
    ]
}
```

Because there is no further configuration, only the `kind` key is required.

This push rule *should* trigger when any room listed in `m.direct` account data
gets a message. This is regardless of the member count.

## Unstable prefix

Before this makes it into the spec, the push rule should use
`eu.cyrneko.msc4563.direct_message` as the `kind` field.

The `rule_id` should be `eu.cyrneko.msc4563.direct` and
`eu.cyrneko.msc4563.encrypted_direct` respectively.
